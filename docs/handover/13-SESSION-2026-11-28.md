Langkah menambah satu kelompok:

1. `python tools/survei-formulir.py` untuk daftar, lalu `python tools/survei-formulir.py RMxxx RMyyy` untuk kolom, label, isian wajib, panjang, pilihan dan izin.
2. Baca di Java handler Simpan, Ubah, Hapus dan rumus skornya. Jangan menyamaratakan aturan waktu: formulir observasi memakai batas 2 x 24 jam, waktu registrasi dan tanggal mundur, sedangkan Penilaian Lanjutan Risiko Jatuh Dewasa tidak satu pun (`Batas48Jam`, `CekWaktuRegistrasi`, `IkutKunciTanggal`).
3. Tulis definisi di berkas per kelompok (contoh `Data/RekamMedis/FormObservasi.cs`), beri `Kelompok`, lalu daftarkan di `FormKlinisKatalog.Semua`. `Pilihan` harus sama urutannya dengan enum kolom; pilihan awal yang berbeda diisi lewat `Awal`. Kolom pemilik yang namanya tidak mengikuti jenis pemilik diisi `KolomPemilikKhusus`.
4. Skor memakai `Hitung` (isian `Otomatis: true`); aturan antar isian memakai `Periksa`.
5. Tambahkan tabel ke daftar `simrs_formklinis_fixture` di `tools/uji-fixture.ps1`, lalu jalankan skripnya. `FormKlinisTests` mengisi semua formulir dengan nilai generik ("1" untuk teks, pilihan terakhir) dan mencocokkan skema serta keterhubungan tile.
6. Cocokkan panjang, isian wajib, pilihan dan izin dengan Java. Pada sesi ini dilakukan dengan tes sementara yang menulis definisi ke JSON, dibandingkan dengan keluaran alat survei; skrip pembandingnya tidak disimpan.
7. Perbarui `status.json` (Simpan, Ubah, Hapus, Cetak tiap jendela), [audit rekam medis](../tracker/AUDIT_REKAM_MEDIS.md), README, lalu `node tools/peta-fungsi.mjs --java ../simrs-khanza/src` dan `node tools/tracker.mjs`.

Belum didukung mesin: pemilik ganda, bentuk kunci lain, kolom tanggal tambahan, kolom desimal yang diketik, tabel tambahan, dan gambar.

## Cara kerja dan jebakan

- Pemilik berkomunikasi dalam bahasa Indonesia santai. Commit, push, build EXE dan release hanya bila diminta.
- Gunakan skema sintetis. Akses database rumah sakit memerlukan persetujuan pemilik sistem.
- Build di mesin pengembang: set `MSBuildEnableWorkloadResolver=false`, tambahkan `-m:1 -p:UseSharedCompilation=false -p:NuGetAudit=false`.
- `core.hooksPath` sudah menunjuk `.githooks`: tiap commit membuat ulang laporan tracker.
- Sebagian berkas memakai BOM atau CRLF; pertahankan saat mengubah dengan skrip.
- Cek layar: buat tes sementara `ZzSementara*Tests.cs` dengan Avalonia headless, set `DatabaseSettingsStore.FilePath` ke berkas yang tidak ada, dan hapus tes beserta `src/SimrsGramedika.Tests/TestResults` sesudahnya. Untuk layar berdata, salin `tools/uji-fixture.ps1` ke folder sementara, ganti bagian tesnya, dan set `SIMRS_DB_HOST/PORT/NAME/USER` ke fixture. Panggilan database dari thread tes headless harus lewat `Task.Run`, kalau tidak buntu sampai batas waktu.
